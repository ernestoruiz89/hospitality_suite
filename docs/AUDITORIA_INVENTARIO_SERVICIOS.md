# Inventario, compras y servicios — 0.7.4

El contraste de las nueve entradas pendientes de S11 encuentra dos diferencias funcionales y una de presentación. Devolver un consumo sin facturar revertía su cargo, pero dejaba activos sus descuentos/cortesías. Ahora revierte también los ajustes pendientes asociados, con el mismo motivo y dentro de la transacción. Una cantidad explícita cero se interpretaba como uno; se rechaza antes de crear la solicitud. Las cantidades omitidas conservan el valor predeterminado uno.

Existencias por ubicación conserva el establecimiento, el almacén y la versión de cada consulta. Una respuesta o un error anterior no sustituye la selección vigente, una Page recreada ni los datos de otra propiedad. Muestra carga, vacío, falta de configuración y error con reintento. Los nombres se escapan y activos, ceros, mínimos y alertas tienen textos distintos. La consulta sigue usando Bin, Item Reorder y la clasificación HS; no crea otro libro de existencias. El selector mide 44 px y la ficha móvil usa dos columnas.

Actualizar servicio ofrece solo transiciones permitidas desde su estado actual. La acción principal dice Iniciar preparación, Confirmar entrega, Cancelar solicitud o Confirmar devolución. Las observaciones aparecen para cancelación; la devolución exige motivo. Los servicios terminados no tienen otra acción y una devolución requiere Gerencia/Administración. Se conserva el flujo separado de venta directa y su devolución nativa. No se cambia la política: los consumos a habitación descuentan al entregar mediante Stock Entry; la factura lleva update_stock=0. Un POS independiente puede descontar mediante su Sales Invoice estándar; no son dos salidas para el mismo consumo.
